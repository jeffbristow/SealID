# CLAUDE.md — Seal ID

Self-hosted, Keybase-style identity proofs anchored on an OpenPGP key. One
identity per installation; installations verify and vouch for each other.
The protocol is in `docs/PROTOCOL.md` — read it first; code must match it.

Part of the Seal family (Seal Post, Seal Chat): same dark slate + "sealed"
green design (`src/assets/site.css`), logo `src/assets/seal-id.svg`.

## Layout

`src/` is exactly what gets uploaded to a web host (the install root).

| path | purpose |
|------|---------|
| `src/index.php` | public profile page |
| `src/check.php` | public checker page (1.5.0): "whose Seal ID is this domain / address?" |
| `src/admin.php` | owner's admin (login, profile, proofs, vouching, mirrors); JSON actions via `?a=` |
| `src/api.php` | public JSON API (bundle, status, inbox, reach, lookup) |
| `src/setup.php` | first-run setup (needs `SETUP_CODE` from `config.php`) |
| `src/config.example.php` | copy to `config.php` (git-ignored) |
| `src/lib/bootstrap.php` | config, data dir, security headers, CSP nonce, sessions, JSON helpers |
| `src/lib/openpgp.php` | pure-PHP OpenPGP parser + signature verifier (Ed25519 legacy/v6, RSA) |
| `src/lib/chain.php` | payload building, chain verification, appending, bundle writing |
| `src/lib/http.php` | SSRF-guarded HTTPS fetch + DNS TXT |
| `src/lib/proofs.php` | proof registry, tokens, status cache, re-checks |
| `src/lib/proofs/*.php` | one checker per service |
| `src/lib/peers.php` | fetching/verifying other identities, pinning, vouches, inbox; results carry a `code` (1.5.0) |
| `src/lib/check.php` | public checker (1.5.0): input cleanup, verdicts (pure `check_result`), cache, per-IP + global limits, owner switch (`settings.json`) |
| `src/lib/view.php` | shared HTML (head, header, footer) |
| `src/lib/avatar.php` | profile picture: GD re-draw, pending → signed, serving, peer fetch (1.1.0) |
| `src/lib/update.php` | one-click updates from signed GitHub release packages, undo (1.1.0) |
| `src/lib/proofs/sealchat.php` | Seal Chat proofs: same key, or attestation signed by the Seal Chat key (1.2.0) |
| `src/assets/keystore.js` | optional saved key: on this device (passkey PRF / passphrase) or encrypted server copy (1.2.0) |
| `tools/release.mjs` | builds + signs `dist/SealID-<v>.zip(.sig)` from the tag |
| `src/assets/` | css, logo, admin.js, sign.js, bundled OpenPGP.js 6.3.2 (LGPL) |
| `tests/` | CLI tests: `php tests/run.php` (fixtures made by `node tests/make-fixtures.mjs`) |

Data (never in git, never web-readable) lives in `SEALID_DATA` from
`config.php`, default `../.sealid-data` next to the install folder.
`.well-known/seal-id.json` inside `src/` is generated by the app.

## Rules

- No database, no Composer, no build step. PHP 8.1+ with curl, sodium, openssl.
- Never require host changes (no cron, no special modules beyond mod_rewrite-free
  Apache/.htaccess basics). Anything a host might block must have a fallback.
- The private key never reaches the server. The server only verifies.
- Every inline script/style uses the CSP nonce.
- All outgoing fetches go through `lib/http.php` (SSRF guard).
- `config.php` and the data dir are git-ignored; never commit them.

## Testing

PHP 8.1+ with sodium, openssl and curl (plus a CA bundle for live proof
checks). Node 20+ runs the fixture generators with the bundled OpenPGP.js;
`gpg` makes the GnuPG fixtures (incl. a signing-subkey key).

Live tests (need a real host): `tests/live-proofs.php` (run ON the server:
can it reach every service?) and `tests/e2e-peer.mjs` (two installs on real
https addresses: proofs, vouching, inbox, withdrawal, mirror fallback).

## Releases

- Version lives in `SEALID_VERSION` (src/lib/bootstrap.php). Bump, commit, tag `v<x.y.z>`, push.
- `node tools/release.mjs` builds the zip FROM THE TAG and signs it with the Ed25519 key at
  `~/.sealid/update-signing-key.pem` (never commit, never upload). It checks the signature
  against `UPDATE_PUBKEY` in src/lib/update.php.
- GitHub release `v<x.y.z>` must carry exactly `SealID-<x.y.z>.zip` and `SealID-<x.y.z>.zip.sig`,
  must not be a draft/prerelease (installs read /releases/latest). Notes: bullets under
  "## New in Seal ID x.y.z" (the admin page shows the first bullets).
- Changing the signing key means every install must be updated by hand once.

## 1.2.0 rules

- Aliases: a domain is an alias only if the Seal ID it points to has a VERIFIED web/dns proof for it
  (`peer_lookup`). DNS proofs need `id=<url>` in the record to be alias-ready (checks store `alias`).
- DNS key records (`v=sealid1`) apply to the identity named by `id=`, or without it only to the
  identity at the host root — several identities can share a host.
- Saved keys: the server only ever stores ciphertext made in the browser (keystore.js); never add a
  path where the server can sign by itself.
- `Element.append()` prints null as "null": pass '' (el() filters nulls, append does not).

## Hosting lessons

- Shared/clustered hosts can take 10–60 s before web servers see a new file,
  and edge caches can keep a 404. Proof fetches and peer fetches therefore use a
  cache-buster query + `Cache-Control: no-cache`, and peers read `api.php?a=bundle`
  (generated per request) before the static `.well-known/seal-id.json`.
- GitHub API: 60 anonymous requests/hour PER IP, and shared hosts share one IP — often used up by
  neighbours (HTTP 403). The updater falls back to github.com/<repo>/releases/latest (a redirect to
  the tag) + standard download URLs; notes come from the .sig file's "notes" (release.mjs fills it
  from dist/notes-<v>.md).
- Cloudflare (in front of StackCP) caches assets per our Cache-Control (1 day). Module imports between
  scripts (./sign.js) carry no ?v=, so lib/view.php emits an import map that versions every
  assets/*.js|mjs. Never import an asset by a path the import map doesn't cover.
- Reddit blocks datacenter IPs on its JSON API; its oEmbed endpoint works, so the
  Reddit proof lives in the post title.
